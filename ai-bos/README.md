# AI BOS · ทดลองตรวจเงินนำส่ง LAKON

งาน `finance` ตรวจข้อมูลใน `Payments` และ `CashRemits` ได้โดยอิสระจากคุณเลขา ใช้โค้ดเทียบข้อมูลและเก็บผลแบบเงียบ ๆ ชุดทดลองนี้อ่าน JSON จากไฟล์และคืน JSON ทาง stdout จึงรันได้ด้วย Node.js 22 ขึ้นไปโดยไม่ต้องตั้งค่าโมเดลหรือใช้โทเคน

```sh
node ai-bos/finance/run-shadow.mjs 2026-11-24 ai-bos/test/fixtures/lakon-cash.json
```

## ข้อมูลเข้า

- รูปแบบแรกเป็น snapshot ตาม [ตัวอย่างข้อมูลสมมติ](test/fixtures/lakon-cash.json) มี `company: "lakon"`, `throughDate`, `payments` และ `remits` จำนวนเงินเป็นสตางค์เต็ม
- รูปแบบที่สองใช้ `company` และ `throughDate` เหมือนกัน โดยส่ง `valueRanges` ตามรูปแบบ Sheets API จาก `Payments` และ `CashRemits` รวมแถวหัวตาราง ใช้ `UNFORMATTED_VALUE` และ `SERIAL_NUMBER` สำหรับวันที่ที่เก็บเป็นตัวเลข จำนวนเงินในรูปแบบนี้เป็นบาท ตัวแปลงจะเก็บเฉพาะคอลัมน์ที่ใช้ตรวจ
- `throughDate` คือวันที่ตามปฏิทินกรุงเทพฯ ที่ชุดข้อมูลครอบคลุม ชุดข้อมูลต้องรวมรายการกลับรายการและใบนำส่งที่เชื่อมจากวันอื่นด้วย ผลย้อนหลังจาก snapshot ปัจจุบันแสดงสถานะที่ทราบ ณ วันที่อ่าน
- ไฟล์ทดสอบใน repo ใช้ข้อมูลสมมติ เก็บข้อมูลจริงและผลที่มีรหัสรายการไว้นอก git

## อ่านผล

| ประเภท | ความหมาย |
|---|---|
| `unmatched_cash_payment` | ไม่พบใบนำส่งที่เชื่อมกับรายการรับเงินสดนี้ในข้อมูลที่อ่าน |
| `unmatched_cash_refund` | รายการติดลบที่ไม่พบใบนำส่งที่เชื่อม ตรวจแยกจากเงินสดรับ |
| `counted_remit_variance` | ใบนำส่งที่นับแล้วมีส่วนต่างตามที่แอปการเงินบันทึก |
| `*_needs_review` | ลิงก์กลับรายการหรือลิงก์ใบนำส่งขัดกัน หรือใบนำส่งที่นับแล้วขาดยอดส่วนต่าง |

ผลชี้กลับไปที่ต้นทางด้วย `source`, `sourceId` และ `sourceDate` รหัส finding เดิมใช้ซ้ำได้เมื่อรันอีกรอบ ผลจากใบนำส่งใช้วันที่ของใบแม้ถูกพบระหว่างตรวจหลายวัน สำหรับข้อมูลที่ขาดหัวตาราง มีรหัสกำกวม หรือไม่ครอบคลุมวันตรวจ โปรแกรมคืน `check_failed` และ exit code 1

## ทดสอบ Cloudflare Worker กับ D1

```sh
npm --prefix ai-bos ci
npm --prefix ai-bos test
```

ชุดทดสอบใช้ Workerd และ D1 จำลองในเครื่อง ส่ง Cron และข้อมูล LAKON สมมติเข้า Worker แล้วตรวจผลในฐานข้อมูล ไม่มีการเรียกบริการจริง

- ใน [ตัวอย่างค่า Wrangler](worker/wrangler.example.toml) รอบนำร่องคือ 21:30 น. ตามเวลากรุงเทพฯ ค่าตั้งนี้ยังไม่ได้เปิดใช้งาน
- ใช้ D1 แยกสำหรับ AI BOS นำเข้า [migration](worker/migrations/0001_finance_runs.sql) ก่อนเปิดรัน ฐานเก็บผลและสถานะสำเร็จหรือล้มเหลวตามเวลารอบตรวจ เมื่อบันทึกผลสำเร็จแล้ว การรันซ้ำรอบเดิมจะไม่เขียนทับผล
- `LAKON_FINANCE_SOURCE` เป็น Cloudflare service binding ไปยังบริการอ่านภายในที่ต้องจัดขึ้นก่อนเปิดรอบจริง Worker เรียก `GET /snapshot?businessDate=YYYY-MM-DD` ได้เฉพาะชุดข้อมูล LAKON ตามสัญญาข้อมูลด้านบน ให้อ่าน `Payments` กับ `CashRemits` แบบจำกัดสิทธิ์ ป้อนเฉพาะคอลัมน์ที่ต้องใช้ และรวมใบนำส่งหรือรายการกลับรายการที่เชื่อมข้ามวัน
- Worker รองรับ Cron และเก็บผลใน D1 คำขอ HTTP ตอบ 404 การให้คุณเลขาอ่านผลตามสิทธิ์เป็นงานถัดไป

เริ่มใช้งานจริงเมื่อยืนยันสิทธิ์บริการต้นทาง จัด Worker และ D1 ในบัญชี Cloudflare แล้ว จึงทดสอบแบบเงียบตามรอบจริง
